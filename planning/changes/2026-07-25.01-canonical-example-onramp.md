# Design: Canonical minimal-DI example (typer rollout)

## Summary

Ship a canonical, runnable example in `modern-di-typer`: a minimal
`examples/` CLI wiring one `Settings` (APP scope) and one `GreetingService`
(REQUEST scope) into a single command via the real `@inject` + `FromDI`
idiom, an in-memory smoke test (`CliRunner`) that proves it runs, and the
README `Usage example:` line. This rolls out the reusable shape the
`modern-di-faststream` pilot locked
(`planning/changes/2026-07-24.01-canonical-example-onramp.md` in that repo) to
this integration.

## Motivation

The [blessed-ready on-ramp audit](https://github.com/modern-python/modern-di/blob/main/planning/audits/2026-07-22-blessed-ready-onramp-report.md)
found most integrations, including this one, at **D2=1 / D6=1**: a complete
inline README example but no dedicated, linked `examples/` dir, so neither the
`Usage example:` line (D6) nor a D2=2 score is reachable. faststream piloted
the fix; this change applies the same locked pattern here.

## Design

**The example** — `examples/app.py` (+ `examples/__init__.py`): the smallest
runnable typer CLI that demonstrates the recommended wiring, matching the
README snippet's shape but as a complete program:

- `Settings` — `providers.Factory(scope=Scope.APP, creator=Settings)`.
- `GreetingService` — `providers.Factory(scope=Scope.REQUEST, ...)`, depends on
  `Settings` by type (auto-injected).
- one `@app.command()` decorated with `@inject`, taking `name` as a CLI
  argument and `service` via `typing.Annotated[GreetingService,
  FromDI(Dependencies.service)]`; the command echoes `service.greet(name)` so
  a test can assert real output in `stdout`. `setup_di(app, container)` wires
  the app; a `if __name__ == "__main__": with container: app()` boot block
  matches the repo's documented root-open lifecycle (`with container:` per
  the README), marked `# pragma: no cover` as the one genuinely unreachable
  line under test.

**Smoke test** — `tests/test_example.py`: imports the example's `app` and
`container`, opens the APP-scope container (`with container:`, mirroring
`tests/conftest.py`'s fixture), and invokes the command via
`typer.testing.CliRunner().invoke(app, ["world"])` — the repo's own in-memory
test idiom, already used throughout `tests/test_commands.py`. Asserts
`result.exit_code == 0` and the real injected greeting in `result.stdout`
(`"Hello, world!\n"`).

**Coverage** — none excluded except the single `# pragma: no cover`d
`__main__` boot line (unreachable under test by construction — running the
script standalone bypasses the test process). The smoke test imports and
invokes the command, executing every other line, so it covers the example to
**100%** under the repo's existing `--cov-fail-under=100` gate.

**README** — insert `Usage example: [examples/](./examples)` directly under
the `Full guide` line, above `## Installation`, matching the faststream
placement.

No `modern_di_typer/` source changes, so no `architecture/` promotion — this
adds documentation-grade example + test, not a capability change.

## Non-goals

- A realistic/DB starter — minimal DI demo only, per the locked pattern.
- New runtime dependencies — the example uses only `typer` + `modern-di`,
  already present.
- Editing the inline README `## Usage` snippet or any integration behavior.
- `Scope.ACTION` / `action_scope` usage — out of scope for the minimal
  example; the README's own "Action scope" section already covers it.

## Testing

- `just test-ci` green: the smoke test covers `examples/app.py` to 100%
  (only the `__main__` boot line pragma'd) and invokes a real command
  asserting the injected service's real greeting in stdout.
- `just lint-ci` green (ruff/ty/eof/format over the new files).
- `just check-planning` green (this bundle validates).
- Manual sanity: `python -m examples.app world` prints `Hello, world!` when
  run directly (documented, not a CI gate).

## Risk

- **Example rot** (low x low) — mitigated structurally: the example is
  measured (no coverage exclusion beyond the boot line) and the smoke test
  executes it every CI run, so a broken or uncovered example fails the build.
- **Example drifts from the README snippet** (low x low) — they share one
  shape; keep the example the runnable superset of the snippet.
